# 퀵 정렬과 AVL 트리 정렬의 성능 비교

## 1. 실험 개요 및 피벗 선택 방법
* **실험 환경**: C 언어 (64-bit 환경 기준 `sizeof(int) = 4 Bytes`, `sizeof(AVLNode) = 32 Bytes`)
* **퀵 정렬 피벗 선택 방법**: 분할 구간 `[left, right]`의 정중앙 인덱스 원소(`arr[(left + right) / 2]`)를 피벗으로 선택하는 호어(Hoare) 분할 방식을 사용하였습니다. 이미 부분적으로 정렬된 구간이나 중복 데이터가 포함되더라도 편향 분할(Worst-case $O(n^2)$) 가능성을 낮추고 평균 $O(n \log n)$ 성능을 유지합니다.
* **중복 데이터 처리**: 배열은 동일 값을 인접 인덱스에 중복 저장하며, AVL 트리는 노드 내부에 `count` 변수를 두어 중복 키 삽입 시 노드를 추가 생성하지 않고 `count`를 증감하도록 구현하였습니다.

## 2. 두 방법의 총 수행시간 및 비교 횟수 차이
* **초기 정렬 단계**: 퀵 정렬과 AVL 트리 생성 모두 평균 $O(n \log n)$의 비교 횟수가 소요되지만, 퀵 정렬은 연속된 배열 메모리를 순차 참조하므로 CPU 캐시 효율(Cache Locality)이 뛰어나 순수 초기 정렬만 수행할 때는 AVL 트리보다 빠르게 동작합니다.
* **삽입·삭제 포함 전체 단계**: $m = 0.2n$회의 동적 삽입·삭제가 결합되면서 전체 비교 횟수와 수행시간의 우위가 역전됩니다.
  * **퀵 정렬(정렬된 배열)**: 매 삽입·삭제마다 위치를 찾기 위해 선형 탐색($O(n)$)을 수행하므로 $m$회 연산 시 평균 $O(m \cdot n) = O(n^2)$의 비교가 발생합니다. (예: $n=20,000, m=4,000$일 때 약 5,400만 회 비교)
  * **AVL 트리**: 엄격한 균형 이진 탐색 트리(높이 $h \le 1.44 \log_2 n$)를 유지하므로 삽입·삭제 탐색 시 매번 $O(\log n)$의 비교만 수행합니다. 전체 과정에서 $O((n + m) \log n)$ 비교에 그치며, $n=20,000$ 기준 비교 횟수가 약 56만 회로 배열 방식 대비 약 1/100 수준에 불과합니다.

## 3. 삽입·삭제 과정에서 발생하는 데이터 이동 횟수 차이
* **배열(Quick Sort 이후 조작)**: 물리적으로 연속된 메모리 공간을 유지해야 하므로, 인덱스 `pos`에 원소를 삽입하거나 삭제할 때마다 뒤에 위치한 평균 $n/2$개의 원소를 한 칸씩 밀거나 당기는 시프트(Shift) 연산이 발생합니다. 따라서 $m$회 연산 동안 $O(m \cdot n) = O(n^2)$의 대규모 데이터 이동이 일어납니다.
* **AVL 트리**: 노드가 포인터로 연결된 비연속적 구조이므로, 새로운 값을 삽입할 때 다른 노드의 데이터를 이동할 필요 없이 신규 노드에 키를 대입(1회)하고 포인터만 연결합니다. 삭제 시에도 자식이 2개인 노드를 제거할 때만 중위 후계자(Inorder Successor)의 키 값을 복사(1회)하며, 불균형 복구를 위한 회전(LL, RR, LR, RL) 역시 포인터 참조만 변경할 뿐 데이터 값 자체의 이동은 발생하지 않습니다.
* **결과**: $n=20,000$에서 배열은 약 2,000만 회의 데이터 이동이 발생하는 반면, AVL 트리는 약 1.4만 회로 1,400배 이상 적은 데이터 이동을 기록합니다.

## 4. 배열과 AVL 트리의 메모리 사용량 차이
* **배열**: 원소 1개당 `sizeof(int) = 4 Bytes`만 요구하며, 최대 데이터 크기 $(n + m)$개를 수용하더라도 $4 \times 1.2n$ Bytes와 퀵 정렬 재귀 호출 스택(수백 Bytes)만 사용합니다. ($n=20,000$일 때 약 96 KB)
* **AVL 트리**: 각 노드(`AVLNode`)마다 데이터 키(`4 Bytes`) 외에도 중복 카운트(`4 Bytes`), 높이(`4 Bytes`), 패딩(`4 Bytes`), 좌·우 자식 포인터(`8 Bytes` $\times 2 = 16$ Bytes)가 포함되어 노드당 `32 Bytes`가 소요됩니다.
* **결과**: 중복 키가 일부 병합되더라도 AVL 트리는 포인터와 균형 제어 메타데이터 오버헤드로 인해 배열 대비 약 4~5배 많은 메모리 공간을 사용합니다.

## 5. 데이터 크기 증가에 따른 성능 변화
* 데이터 크기 $n$이 1,000에서 20,000으로 20배 증가할 때 연산 횟수 $m(0.2n)$도 함께 20배 증가합니다.
* **배열 방식**: 삽입·삭제의 시간 복잡도가 $O(m \cdot n) = O(0.2n^2) = O(n^2)$를 따르므로, 데이터 크기가 2배 증가할 때마다 비교 횟수, 데이터 이동 횟수, 총 수행시간이 약 **4배씩 기하급수적으로 증가**합니다.
* **AVL 트리 방식**: 전체 시간 복잡도가 $O((n + m) \log n) = O(n \log n)$을 따르므로, 데이터 크기가 2배 증가해도 수행시간과 비교 횟수는 약 **2.1~2.2배 수준으로 완만하게(준선형적으로) 증가**합니다.

## 6. 삽입·삭제가 반복되는 환경에서 유리한 자료구조와 그 이유
* **유리한 자료구조**: **AVL 트리**가 압도적으로 유리합니다.
* **구조적 이유**:
  1. **탐색 비용의 차이**: 배열은 선형 탐색에 $O(n)$이 걸리지만(이진 탐색을 쓰더라도 시프트 비용 때문에 전체 시간 복잡도는 여전히 $O(n)$), AVL 트리는 회전 연산을 통해 트리 높이를 항상 $O(\log n)$으로 강제하므로 최악의 경우에도 $O(\log n)$ 탐색을 보장합니다.
  2. **구조 변경(재배치) 비용의 차이**: 배열은 논리적 순서와 물리적 메모리 순서가 일치해야 하므로 삽입·삭제 시 $O(n)$의 메모리 복사(Shift)가 불가피합니다. 반면 AVL 트리는 논리적 순서를 포인터 연결로 표현하므로, 삽입·삭제 후 최대 $O(\log n)$개의 조상 노드 높이 갱신과 상수 시간($O(1)$)의 포인터 회전만으로 정렬 상태와 균형을 동시에 유지합니다.
* 따라서 **초기 1회 정렬 후 조회만 수행하는 정적(Static) 환경**에서는 메모리 효율과 캐시 지역성이 뛰어난 **퀵 정렬(배열)**이 유리하지만, **정렬 상태를 유지하면서 데이터의 삽입과 삭제가 빈번하게 발생하는 동적(Dynamic) 환경**에서는 메모리 오버헤드를 감수하더라도 **AVL 트리**를 사용하는 것이 성능상 필수적입니다.
